With 750 labelled tweets, does fine-tuning beat a calibrated open LLM?

Research question (unchanged)

If we only have 750 labelled tweets, does fine-tuning BERTurk give a higher macro-F1 on the official OffensEval-TR 2020 test set (3,528 tweets) than prompting an open LLM (Gemma-2-9B-it or Qwen3-8B) that uses the same 750 tweets: 8 as prompt examples, and the other 742 to choose its decision threshold?

The answer is no if

against either LLM, BERTurk’s average over 10 runs is not at least 0.02 higher than the LLM’s average over 3 runs, or a paired bootstrap test says the gap could be chance.

7 · Why calibration helps Qwen much more than Gemma

Qwen is shifted; Gemma’s threshold is already near optimal

F1 @ 0 uses threshold 0; F1 @ best is the best threshold. Mean OFF/NOT are mean log P(A) − log P(B). Chart: Qwen3-8B, one run.

What explains the gap

  • Not the tokenizer. Gemma is more compact on these tweets: 32.3 vs 37.9 tokens/tweet.
  • Qwen is shifted, not blind. At threshold 0 it calls 99% of tweets offensive, but the ranking is usable: best-threshold F1 is 0.677.
  • Gemma is already centred. F1 at 0 is 0.763 and best is 0.765, so the 742 labels add only +0.027.
  • The 8 examples still help Qwen: 0.677 → 0.773 after calibration.

This is threshold geometry, not proof of contamination. It does not isolate pretraining language from alignment; the exact-completion check is still planned.

Fields 1–3: title and abstract, research question, contributions

1 · Title and abstract

Working title: Fine-tuning BERTurk vs threshold-calibrated open LLMs for Turkish offensive language with 750 labels.

Small Turkish platforms can label only a few hundred tweets. We ask whether fine-tuning BERTurk on 750 labelled OffensEval-TR tweets beats an open LLM that uses the same 750 labels as 8 prompt examples and 742 calibration tweets for its decision threshold. The TF-IDF + logistic-regression baseline scores 0.763 macro-F1 on the frozen 3,528-tweet test set, but 0.620 with 750 labels. The LLM arm scores each tweet as log P(A) − log P(B); the 742 labels set its threshold. On dev, calibration moves Qwen3-8B from 0.162 to 0.628 and Gemma-2-9B from 0.412 to 0.500; Qwen3-14B reaches 0.773 (zero-shot 0.171) and Gemma-4-12B 0.790 ± 0.007 (zero-shot 0.763). Fine-tuned BERTurk reaches 0.767 ± 0.014 on dev with 750 labels. Gap: the frozen-test comparison is pending; the final result uses the paired bootstrap.

2 · Research question

Unchanged. With 750 labels, does fine-tuning BERTurk beat prompting Gemma-2-9B-it or Qwen3-8B using the same 750 tweets (8 examples, 742 threshold labels) on macro-F1 over the official 3,528-tweet test set?

“No” result: BERTurk’s mean over 10 runs is not ≥0.02 above the LLM’s mean over 3 runs, or the paired bootstrap says chance (p ≥ 0.05). Change: none.

3 · Contributions

C1. At 750 labels, we test whether BERTurk’s mean test macro-F1 is ≥0.02 above each LLM’s and whether a paired bootstrap rejects chance. Test pending; on dev BERTurk 0.767 vs 0.628 / 0.500.

C2. The 742-label threshold improves each LLM’s dev macro-F1 over zero-shot; we report per-model delta and spread.

C3. The learning curve tests where fine-tuning overtakes TF-IDF between 250 and 6,000 labels; if the lines never cross, the 750-label answer stands.

Fields 6–9: method, protocol, results so far, error analysis

6 · Method and baseline

TF-IDF word 1–2 + char_wb 2–5, min_df=2, sublinear, Turkish lowercasing; LR C=1.0, balanced. Test 0.763 [0.745, 0.779].

Fine-tuning: BERTurk/XLM-R, 128 tokens, batch 16, 2e-5, 4 epochs or 400 updates, class-weighted, no early stopping. LLM: Qwen/Gemma 4-bit, 8 examples, 742-label threshold. One change: labels train weights vs choose examples and threshold.

Compute: 2.4 GPU-h fine-tuning (46 runs) + 2.5 L4-h for 16 LLM passes.

7 · Evaluation protocol

Macro-F1; frozen 3,528-tweet test; 10 BERTurk runs at 250/750/2,000 and 3 at 6,000/30,000; 3 runs per LLM at 750. Paired bootstrap, 10,000 resamples; real gap ≥0.02 and wins on ≥95%. Fixed before method results; dev for code checks only.
